# template-python-app-no-assets

The most minimal app build: **code only, no data files**. Same application as
[`template-python-app-root-asset`](../template-python-app-root-asset/README.md) and
[`template-python-app-assets-dir`](../template-python-app-assets-dir/README.md) — same
`wordstats/` code, same dependencies, same output format — but the input text is a
lorem ipsum constant hardcoded in `main.py`, so there is no `words.txt` to ship.

## The three app templates compared

| | `…-root-asset` | `…-assets-dir` | `…-no-assets` (this one) |
|---|---|---|---|
| Input text comes from | `words.txt` in the repo root | `assets/words.txt` | hardcoded `LOREM_IPSUM` in `main.py` |
| `rootAssets` in `metadata.yaml` | `true` | `false` | key absent (default off) |
| Extra package for data | `_root_assets`, generated by the forge | `assets`, your own | none |
| Files shipped besides code | every non-`.py` root file (incl. READMEs) | contents of your asset packages | none |
| Good for | showing the root-asset feature | data files, the recommended way | small apps and scripts without data |

Use this variant whenever the app does not need external files; reach for the
assets directory as soon as it does.

## Contents

| File | Purpose |
|---|---|
| `metadata.yaml` | Name, version, Python version, how to start the app |
| `requirements.txt` | Pinned dependencies (`tabulate`, `humanize`), rules as in [`../template-python-venv`](../template-python-venv/README.md) |
| `main.py` | Thin entrypoint with the hardcoded input text |
| `wordstats/` | The application code as a small package (`__init__.py` + `stats.py`) |
| `README_technical.md` | API/curl/GitWatcher details |

## What the forge does with it

1. Reads `metadata.yaml`, builds a Python 3.12 venv from `requirements.txt`.
2. Copies every top-level directory that is a Python package — here only `wordstats/` — into the venv.
3. Uploads the venv pack, `main.py` and `metadata.yaml` to fusion-index as `app.template-python-app-no-assets`, version `0.1.0`.

Nothing from the repo root other than `main.py` and `metadata.yaml` is shipped.

## Layout rules

- `main.py`, `metadata.yaml` and `requirements.txt` are required in the repo root (or configured sub-directory).
- Code in sub-directories must be an importable package, i.e. contain an `__init__.py`.
- Bump `version` in `metadata.yaml` to publish a change; an existing version is not rebuilt.
- `runner.type: python` runs the entrypoint once, with no port and no ingress.

## How to use it as a template

1. Copy this directory, e.g. `cp -r template-python-app-no-assets my-app`.
2. Set your own `name`, `version`, `maintainer` in `metadata.yaml`.
3. Replace `wordstats/` and the logic in `main.py`; keep `__init__.py` in each package.
4. Pin your dependencies, push, and let the forge build it from Spectra.

For the API view see [README_technical.md](README_technical.md).
